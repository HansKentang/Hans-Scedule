# Havën Schedule — Full Codebase Audit

_Date: 2026-09-19 · Read-only audit · No files were modified_
_Scope: all HTML, CSS, and JS in the project root, plus PWA plumbing and git/deploy configuration_
_Method: six parallel readers, one per slice; every Critical and High finding independently re-verified by direct file inspection before inclusion. Verification status is marked on each finding._

---

## Executive summary

The app is feature-rich and the core interactions are better engineered than the file sizes suggest — drag/resize conventions, undo/redo storage, and JSON parsing are mostly correct. The problems cluster in three places: **the deployment is broken** (the service worker can never install on GitHub Pages), **`escapeHtml()` does not escape quotes**, which turns every attribute context into a stored-XSS sink, and **authorization is entirely client-side with no security rules in the repository**. Separately, the hub page leaks a network-polling map and a 5-per-second localStorage write loop.

**The five things to fix first:**

| # | Issue | Impact |
|---|---|---|
| 1 | Service worker + manifest use root-absolute URLs | PWA install fails on your GitHub Pages subpath — offline support has never worked when deployed |
| 2 | `escapeHtml()` does not escape `"` | Stored XSS; exploitable cross-user through friends/chat profile fields |
| 3 | No Firestore security rules in repo | Cannot verify any data is protected; all authorization is client-side |
| 4 | Hardcoded admin password in two files | `MjcwODEw` = base64 of a 6-digit number, shipped in source |
| 5 | Hub re-render leaks Leaflet maps + intervals | Unbounded memory and network growth while the app is open |

## CRITICAL

### C1. Service worker install fails on the deployed subpath — `[verified]`
`service-worker.js:3-42`

All 38 precache entries are root-absolute (`'/index.html'`, `'/css/style.css'`). The repo deploys via `.github/workflows/deploy.yml` (uploads `.` as the Pages artifact) from `github.com/HansKentang/Hans-Scedule`, so the app is served at `https://hanskentang.github.io/Hans-Scedule/`. On that path, `cache.addAll` requests `https://hanskentang.github.io/index.html` → 404 → the install promise rejects → **the service worker never activates**. It works on your local server only because that runs at the domain root.

Every one of the 38 paths exists on disk, so the list itself is complete — the bug is purely the leading slash.

**Fix:** make every URL relative — `'index.html'`, `'css/style.css'`, `'./'`.

### C2. Manifest points outside its own scope — `[verified]`
`manifest.json:5, 33, 34`

`"start_url": "/index.html"`, `"scope": "/"`, `"id": "/"`. On the subpath deployment the start URL resolves outside the declared scope, so installation and launch target the wrong location. `id: "/"` also ties the app's identity to the shared origin root.

**Fix:** `"start_url": "./index.html"`, `"scope": "./"`, and drop `id` or set it to `"./"`.

### C3. `escapeHtml()` does not escape quotes — stored XSS — `[verified]`
`js/shared.js:2825-2829`

```js
function escapeHtml(str) {
  const div = document.createElement('div');
  div.textContent = str;
  return div.innerHTML;
}
```

This escapes `&`, `<`, `>` — but **not `"` or `'`**. Every place it is used inside an HTML attribute is therefore injectable. A value like `x" onerror="alert(1)` breaks out of the attribute.

Confirmed sinks in attribute position:
- `js/friends.js:351, 355, 384, 585, 588, 589, 643, 646, 775` — profile `photoURL` / `data-*` attributes. `avatarColor` is interpolated with **no escaping at all**. These are *other users'* fields, so this is exploitable **across accounts**: a malicious user writes the payload to their own `users/{uid}` doc, and it executes in every friend's browser.
- `js/shared.js:875, 4796, 7111-7112` — category labels in `value="…"`
- `js/goals.js:605, 924`, `js/gallery.js:286` — `value="${…}"`, `src="${…}"`

**Fix:** escape `& < > " '` explicitly in `escapeHtml`, or build nodes with `setAttribute`/`textContent`.

### C4. No Firestore security rules in the repository — `[verified: file absent]`
No `firestore.rules`, no `firebase.json`. Authorization is entirely client-side:
- `js/admin.js` gates the admin panel with a client-side password check and performs **zero** Firestore writes — so this is *not* server privilege escalation, but see C5.
- `js/chat.js:33-56, 120-180` — conversations are fetched by `conversationId` only, with no participant filter; `from` and the unread counters are client-supplied. Without server-side rules, a user could read or inject into any conversation and spoof a sender.
- `js/friends.js:126`, `js/firestore-sync.js:157, 317` — friend codes derive from `Math.random()` and are enumerable via `where('friendCode','==',…)`.
- Profiles created in "local" mode never call `signIn*`, yet still read/write the shared `users`, `conversations`, `messages`, `friends`, `challenges`, and `activity` collections.

**Cannot be resolved from source.** You must check the rules in the Firebase Console. If they are not `request.auth != null` with per-user checks, the entire database is world-readable and every client-side check is decorative.

### C5. Hardcoded admin password, shipped twice — `[verified]`
`js/hub-visuals.js:785` and `js/admin.js:10`

```js
var ADMIN_PASS = 'MjcwODEw';   // base64 of "270810"
```

Also auto-written to `localStorage` as `haven-admin-password`, and `sessionStorage['haven-admin-authed'] = 'true'` bypasses the prompt. Anyone reading the source has the password. `admin.html` loads only `shared.js` + `admin.js`, so it never redirects signed-out users either.

**Fix:** remove the default, fail closed, and don't gate anything meaningful on a client-side check.

## HIGH

### H1. Times past midnight are persisted as invalid strings — `[verified]`
`js/schedule.js:2027-2028, 2081-2082, 2201, 792, 497` + `js/shared.js:2779-2783`

```js
function toTimeStr(minutes) {
  const h = Math.floor(minutes / 60);   // no % 1440
  ...
}
```

`dropTime` can reach `clampHi = 1725`, and `repelConflicts`/`onResizeEnd` can reach 1740. So the app writes `"28:45"` and `"29:00"` into task records. These are invalid for `<input type="time">` (which then blanks them), corrupt durations, and the `+` button on the 4am row produces `"28:15"`.

**Fix:** `toTimeStr(minutes % 1440)`, or clamp to the day boundary.

### H2. Work-hours mode mispositions every task by two hours — `[verified]`
`js/schedule.js:1382, 1569, 2143, 2192`

Cards are positioned with `((startM - START_HOUR*60)/60) * actualHH`, but when `weekPrefs.workHours` is on the grid starts at `hStart = 7` (`:346`). Every card, the current-time line, and all resize math are drawn two hours too low.

**Fix:** read the grid's real first slot (`Number(firstCol.dataset.time)`) instead of assuming `START_HOUR`.

### H3. `copyWeekToNext` shifts every task back one day — `[verified]`
`js/schedule.js:3649`

`new Date("YYYY-MM-DD")` parses as UTC midnight; `formatDate` then reads local fields. In any negative-UTC zone a Saturday task is copied to Friday. Elsewhere the file correctly uses `new Date(t.date + 'T12:00:00')` (`:1317`).

### H4. Dragging a recurring task is a silent no-op that still corrupts other tasks — `[verified]`
`js/schedule.js:1643-1644, 2024-2026, 2102`

Card `dataset.taskId` holds the instance id (`orig_YYYY-MM-DD`, `:1399`), so `getTask()` returns nothing and `gridDrag.taskId` is never set — but `repelConflicts(...)` still runs at `:2024` with `excludeId = null` and can rewrite the times of *real* tasks. Resize does nothing at all.

**Fix:** resolve through `resolveTaskId()` in `startDrag`/`onResizeStart`, and abort the drop if no task resolves.

### H5. localStorage quota errors are swallowed, causing silent data loss — `[verified]`
`js/shared.js:1869-1878`

The `setItem` wrapper catches `QuotaExceededError` and returns `undefined` rather than throwing. This makes the app's own quota handling dead code: `saveSleepLogs` (`:158`) returns `true` after a failed write because `getItem` still returns the *old* value, and `saveSidebarConfig` (`:4757`) can never reach its "storage might be full" toast. With base64 images in storage, users lose data with no warning.

**Fix:** return a boolean from the wrapper and check it, or re-throw after the cleanup attempt.

### H6. One corrupt value breaks all subsequent initialisation — `[verified]`
`js/shared.js:2922, 2920-2975`

`loadState()` does `state.tasks = JSON.parse(tasks)` with no `Array.isArray` guard, and *all* remaining setup — settings, API key, custom tags, custom categories, card colours, user profile, images — sits inside the same single `try`. A corrupt or non-array `haven-schedule-tasks` value throws, and the `catch` silently abandons everything after it.

**Fix:** guard with `Array.isArray`, and split initialisation into independent try blocks.

### H7. Hub re-render leaks Leaflet maps and a 15-second polling interval — `[verified]`
`js/hub-visuals.js:1025` vs `js/hub-visuals.js:1895-1899`

```js
grid.innerHTML = '';              // line 1025 — wipes the grid

// ... 870 lines later ...

grid.querySelectorAll('.fr24-widget').forEach(function(el) {   // line 1895
  if (el._flightInterval) clearInterval(el._flightInterval);   // never runs
  if (el._leafletMap) { el._leafletMap.remove(); ... }         // never runs
});
```

The cleanup block queries a grid that was already emptied 870 lines earlier, so it is dead code. Every re-render leaks a Leaflet map, its `moveend`/`zoomend` handlers, and a live `setInterval(fetchFlights, 15000)` (`:2050`). Re-renders happen on every style toggle.

**Fix:** move the cleanup block above line 1025.

### H8. A localStorage write loop that never stops — `[verified]`
`js/hub-visuals.js:4507, 4522-4543`

`_loadTimerStates()` calls `_startTimerTick()` whenever the state key exists — even if no timer is running. The tick body unconditionally calls `_saveTimerStates()` every 200 ms, and `_timerClearTickIfIdle` only runs on toggle or complete. After a user ever uses a timer once, **every subsequent page load starts a permanent 5-writes-per-second `localStorage.setItem` loop.**

**Fix:** only start the tick when at least one timer has `running === true`.

### H9. The hub is hidden on mobile, but all its intervals still run — `[verified]`
`index.html:543-545, 593-595` + `js/hub-visuals.js:302`

`HUB_MOBILE_DISABLED` only adds a CSS class (`style.css:8832` hides `.hub-main > *`). `init()` then unconditionally runs `initHubLayout()`, `initHubEditMode()` and `renderHubBento()`, so below 768px the canvas is invisible while the clock interval, timer tick, weather/headlines/crypto fetches, and flight-radar polling all still start.

This compounds the positioning problem flagged earlier: the flagship feature is off on the device most of your users hold, *and* it still costs them battery and data.

**Fix:** early-return from `init()` when the mobile-disabled class applies.

### H10. User secrets are synced to a shared collection — `[verified]`
`js/firestore-sync.js:309-312` + `js/firestore.js:72`

`pushToCloud` collects every `haven-*` key except images/device/sync metadata — which includes `haven-schedule-apikey` (the user's Groq/Gemini key, set at `gsi.js:1466`) and `haven-admin-password` (the hash). `syncUserToFirestore` also writes `email` into the public `users/{uid}` doc.

**Fix:** exclude the API key and admin password from push; keep email out of the public profile doc.

## MEDIUM

**Statistics and logic**

- `js/progress.js:1399-1459` — streak stats are computed from `getFilteredTasks()`, which for the default `'week'` filter only includes Monday onward, so the 7-day window always spans a week boundary and breaks the streak. `currentStreak` resets to 0 whenever today has no tasks yet, and `bestStreak` is hard-capped at 7. `[verified: logic]`
- `js/progress.js:1267-1274` — the period filter has no upper bound, so every future-dated task is included in week/month totals, completion rates, and the table.
- `js/progress.js:1705-1716` — the Day-by-Day table sums durations over `!t.completed` tasks only, so Total / Deep Work / Study columns omit finished work and won't reconcile with the summary cards. The "Tasks" column shows pending, not total.
- `js/goals.js:269-278` — `calcResolutionStreak` iterates oldest→newest and `break`s past index 6, keeping a stale count. Only the current week checked should give 1; it gives 0.
- `js/goals.js:441-450` — default sort is ascending by progress, so the least-complete goals list first.
- `js/goals.js:327-334` — resolution streak dots all render "M" (derived from Monday keys).
- `finance.html:844-845, 853-854` — range bounds preserve the current time-of-day then compare against midnight, so the earliest day is silently dropped ("7d" covers 6 days).
- `finance.html:868-869`, `js/finance.js:50,173,320,359` — money summed as floats; `fmtMoney` rounds only at display. Store integer rupiah.
- `js/progress.js:742` — `if (html === '')` can never be true (`html` is initialised with the week label at `:690`), so the empty-state block is dead.

**Undo and data lifecycle**

- `js/hub-visuals.js:2857-2872, 2443-2455, 5235-5240, 826-838` — four layout mutations are not undoable: arrow-key nudge, context-menu Reset Size, snap-preset resize, and the edit-exit dimension sync. `pushUndoState()` is called at only 7 sites.
- `js/hub-visuals.js:2062-2068` + `js/shared.js:3229-3241` — deleting an image bubble only splices the layout; the base64 blob stays in `state.images`, IndexedDB, and localStorage forever. Add/delete cycles grow storage without bound. `setImage` also always mirrors to localStorage even when IndexedDB succeeds, defeating the larger store and inviting quota eviction.
- `js/shared.js:3105-3114` — `loadImages()` unconditionally overwrites `state.images` with IndexedDB values while `setImage`/`resetImage` fire unordered async writes, so a reset can be resurrected by an in-flight put.
- `js/shared.js:1437-1457` — `expandRecurringTasks` counts its 365-iteration budget from `task.date`, not the requested window, so a recurring task created over a year ago silently disappears.
- `js/shared.js:1452` — `setMonth(+1)` on the 31st skips months (Jan 31 → Mar 3). Same pattern at `js/schedule.js:2267, 2280` for month navigation.
- `js/firestore-sync.js:231-236, 266, 523-529` — a failed pull sets `SYNC_PULLED_ONCE = true` with no retry, after which push overwrites the cloud doc with stale local data. The 3 s debounce has no unload flush, so offline edits are lost.
- `js/gsi.js:756-801` — sign-out never calls `clearPersistence()`, so Firestore's IndexedDB cache survives. On a shared device the next person can read the previous user's social data.

**Rendering and export**

- `js/schedule.js:3431, 3464, 3559, 3220` — the screenshot export iterates raw `state.tasks` (so recurring instances never appear), throws on any task missing `startTime` (aborting the whole export), paints overlapping tasks on top of each other, and hardcodes `scale = 2` ignoring `devicePixelRatio`.
- `js/hub-visuals.js:5800-5805` — `captureHubSnapshot()` reads `state.hubLayout` (never assigned anywhere in the repo) and `#bentoGrid` (no such id; the grid is `.bento-grid`), so the Snapshot FAB always reports "No bubbles to capture".

- `js/schedule.js:2267-2280`, `:782-784` — midnight-crossing tasks produce negative durations (`-1350m`) in the agenda and undercount week stats.
- `js/schedule.js:3084` — `${TAG_LABELS[tag]}` injected unescaped into templates; `TAG_LABELS` is user-writable.
- `js/progress.js:190, 229, 637, 674` — same unescaped `TAG_LABELS` issue; a category named `<img src=x onerror=…>` executes on every board render.

## Architecture recommendations

**1. Fix the escaping problem at the root.** `escapeHtml` is used in ~200 places and is wrong for attribute contexts. Add a second function (`escapeAttr`) and adopt `setAttribute`/`textContent` in new code. This closes C3 and roughly a dozen smaller sinks at once. It is the single highest-leverage change in this report.

**2. Commit Firestore security rules.** Without them you cannot reason about your own security posture, and every client-side check is cosmetic. Owner-only `users/{uid}`, participant-only conversations/messages, member-only friends.

**3. Split `js/hub-visuals.js`.** 6,110 lines / 372 KB in one scope is why H7 and H8 exist — cleanup code drifts away from the code it must clean up. Suggested split: `hub-layout.js` (normalise/collision/undo), `hub-drag.js`, `hub-widgets-*.js`, `hub-fetchers.js`, `hub-storage.js`, `hub-snapshot.js`. The ~150 lines of copy-pasted style-preference boilerplate at `:19-168` should be one factory.

**4. Add a build step — minimally.** You don't need a framework. You need bundling and minification: 57,000 lines of unminified JS over 29 separate script tags is a heavy load on the mid-range Android devices your market actually uses.

**5. Introduce a lifecycle pattern for widgets.** H7, H8, H9, and the clock/timer leaks are all the same underlying bug: resources acquired at render time with no owner responsible for releasing them. A `mount()`/`unmount()` pair per widget type would prevent the whole class.

**6. Make storage failures loud.** H5 means your quota handling has never once run. Either surface the error to the user or don't pretend to handle it.

**7. Fix `exportAllData()`.** It is currently a partial backup, which is worse than no backup because it creates false confidence.

## What's genuinely good

Worth stating, because the bug list above is long and this is not a bad codebase:

- **Drag/resize conventions hold.** The layout is deep-cloned at drag start and `resolveBubbleCollisions()` runs only on mouseup/touchend, never during mousemove — exactly as documented. Most projects get this wrong.
- **Undo/redo is correct.** `pushUndoState` uses `JSON.stringify` (a true deep copy, no reference aliasing), the stack is bounded to 30 with `shift()`, and redo is properly invalidated. The bug is *missing* call sites, not broken mechanics.
- **z-index layering verified.** `.hub-popup-overlay` = 1001, `.canvas-guide-panel` = 1002.
- **JSON.parse is correctly guarded** in almost every loader — sleep, subcategories, custom tags, chat, AI responses, progress, goals, gallery, finance, settings. `importData` validates its task array. No `eval`, no `document.write`.
- **The service worker's cache logic is sound** — `activate` correctly purges non-matching caches and calls `clients.claim()`, and network-first means online users always get fresh assets. Only the URL format is wrong.
- **No meaningful event-listener leaks** in `schedule.js`, `progress.js`, or `gallery.js` — guards like `_galDragWired` and re-created nodes show care.
- **Completion-rate math is correct** (`done/total` with a zero guard), and sleep averages correctly divide by nights-with-data rather than 7.
- **Manifest icons are real** — `icon-192.png` verified 192×192, `icon-512.png` verified 512×512, and the SVG sits inside the maskable safe zone.
- **Task titles, notes, and chat message text are properly escaped** — the XSS surface is narrower than it first appears, concentrated in attributes and tag/category names.
